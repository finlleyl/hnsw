# G4: kernels and recall-at-QPS

**Setup.** GitHub Actions ubuntu-latest, linux/amd64, AMD EPYC 9V74 (4 vCPU), go1.26.2,
GOAMD64=v1. Run [46171634058](https://github.com/finlleyl/hnsw/actions/runs/46171634058),
source 80a5daa. The measurement module is `docs/measurements/gates`; the root module has no
requirements. Clustered synthetic data from `index_test.go`, n=50000 plus 1000 held-out
queries, M=16, EfConstruction=200, seed 7, k=10. QPS is one goroutine over five seconds per
point. Recall is tie-aware recall@10 against exact distances. Both coder versions use their
CosineDistance; all stored and query vectors are normalized first.

Compared versions are coder/hnsw v0.6.1 (ff889c9) and HEAD 36cab6028fed. coder has one
EfSearch field for construction and search: it is 200 during construction and the tabled ef
during search. Ml is 1/ln(16) for all three implementations.

.99 where this index trails coder HEAD. The assembly consequence is not triggered. In

at any measured point. These figures are one runner and one synthetic dataset, not a general
performance claim.

## Kernel variants

Median ns per dot over three `testing.Benchmark` runs, each using the default calibration:

| d | Scalar | Unrolled 4 | Unrolled 8 | Unrolled 16 |
|---:|---:|---:|---:|---:|
| 128 | 68.8 | 55.0 | 46.3 | 47.1 |
| 768 | 596.3 | 325.2 | 306.2 | 254.9 |
| 1536 | 1233.1 | 639.9 | 625.6 | 505.1 |
| 3072 | 2484.6 | 1268.3 | 1269.4 | 1004.3 |

Unrolled 16 wins at d=768 and above on amd64. The same harness on an Apple M4 Pro confirms
that unrolled 8 remains faster there, so the implementation uses sixteen accumulators in
`dot_amd64.go` and retains eight for other architectures in `dot.go`. The recall/QPS table
above was measured before that selection, with unrolled 8.

The requested reading of hupe1980/vecgo covered v0.0.15 (08c67ffbfe81). Its
[dot kernels](https://github.com/hupe1980/vecgo/blob/08c67ffbfe81d76772f9fb0ae505e92b7cec6cc1/internal/simd/floats_avx2.s)
use runtime-selected AVX2/AVX-512 assembly, unsafe and FMA; the AVX2 loop has four vector
accumulators. None of that code or its dependencies was imported: assembly and unsafe remain
outside v1 scope.

## Reproduce

From `docs/measurements/gates`:

```sh
go run ./g4 -mode=kernel
go run ./g4 -mode=recall -impl=ours
go run ./g4 -mode=recall -impl=coder
go run -modfile=coder-head.mod ./g4 -mode=recall -impl=coder
```

The manual GitHub workflow is `.github/workflows/g4.yml`. It records the host and uploads all
JSONL results. Only darwin/arm64 and the listed hosted linux/amd64 runner were measured;
other CPUs, including amd64 without the same instruction mix, remain open.
